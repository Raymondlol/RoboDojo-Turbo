# AGENTS.md

Instructions for coding agents (and humans) working on RoboDojo-Turbo. README.md explains what the project does;
this file lists what is easy to get wrong.

## What this repository is

A patcher, not a fork. `robodojo_turbo` rewrites a user's local RoboDojo checkout in place (regex-anchored patches,
pinned to upstream file hashes, byte-exact `revert`) and ships the launcher, verification scripts and analysis tools.
Upstream RoboDojo code is never vendored here. Every speedup is off unless its `RDTURBO_*` switch is set; with every
switch off, a patched tree must behave like upstream.

- `robodojo_turbo/engine.py`: apply/revert/status/pins, state directory `<RoboDojo>/.robodojo_turbo/`
- `robodojo_turbo/patches/{harness,speedup,ops}.py`: the patches (`REGISTRY` in `patches/__init__.py`)
- `robodojo_turbo/runtime/`: modules installed into `<RoboDojo>/utils/` as `rdturbo_*.py`
- `robodojo_turbo/cli.py`: CLI and switch validation (`_VALUES`, `_PATTERNS`); `robodojo_turbo/presets/*.env`
- `robodojo_turbo/pins.json`: sha256 of every upstream file a patch may rewrite
- `scripts/`: launcher `rdturbo_eval.sh`, `verify_physics.sh`, `reproduce_benchmark.sh`, `make_figures.py`
- `docs/data/benchmark.json`: measured runs behind every number and figure in the docs

## Commands

```bash
# tests (no GPU); without RDTURBO_TEST_UPSTREAM the patch-matrix tests are skipped
RDTURBO_TEST_UPSTREAM=/path/to/pinned/RoboDojo python -m pytest -q tests
python -m robodojo_turbo apply --root /path/to/RoboDojo --dry-run      # every patch on a scratch copy
python -m robodojo_turbo pins --root /path/to/RoboDojo                 # upstream files vs pins.json
python scripts/make_figures.py                                          # README figures from docs/data/benchmark.json
```

The pinned upstream (CI clones the same): RoboDojo `726e9aa`, XPolicyLab `bb9a0b5` (see `.github/workflows/ci.yml`).

## Rules for changes

- Never hand-edit a patched RoboDojo tree, and never commit upstream code here. Change a patch in `patches/`, then
  `revert` and `apply` again. Revert before `git clean`, `git stash -u` or `git pull` on a patched tree.
- A patch change is done when: the tests pass with `RDTURBO_TEST_UPSTREAM` set, `apply --dry-run` passes, and
  apply-then-revert restores the tree byte for byte (the patch-matrix tests check this per patch and per profile).
- Update `pins.json` only together with a new pinned upstream commit, and re-run the GPU checks below for it. Do not
  widen a regex anchor to make a new upstream file "fit" without that.
- Every injected block starts with a line carrying the marker `[robodojo-turbo]`. Identifiers in injected code use the
  `_rdturbo_` / `_RDTURBO_` prefix (not `_rdt_`: XPolicyLab's RDT_1B policy uses `RDT_*`).
- A new switch needs all of: its patch, an entry in `cli.py` `_VALUES` or `_PATTERNS`, the presets that should set it,
  a row in `docs/switches.md`, and a check mode if a dual path exists. Unset or empty must mean upstream behaviour.
- Upstream owns `ROBODOJO_*`; this project uses `RDTURBO_*` only.
- English only in code, comments and docs. Linux only (like upstream).

## Rules for claims

- Every number in README or docs states its conditions (GPU, task, layouts, envs per batch, runs per arm) and comes
  from `docs/data/benchmark.json` or a run named in `docs/validation.md` / `docs/benchmark.md`. Never extrapolate a
  speedup to tasks, GPUs or Isaac Sim versions that were not measured; list them as unmeasured instead.
- Figures are generated by `scripts/make_figures.py` from the data file; do not edit the SVGs by hand.
- Physics claims rest on open-loop replay (`scripts/verify_physics.sh`: PhysX state decides). Score claims need a
  paired comparison with its noise floor (`tools.paired_compare`); n = 25 is noise-dominated.
- The project is unofficial. Keep the "not affiliated / not leaderboard entries" line, and do not describe local
  results as official RoboDojo scores.

## GPU runs

- Isaac Sim runs take minutes to hours and need an NVIDIA GPU with RoboDojo installed; they are not part of CI.
- Time only on an idle machine: another process on the GPU, or heavy CPU load on the host, changes wall-clock results
  (the simulator's main thread is CPU-bound). `reproduce_benchmark.sh` alternates arm order; keep that.
- Use the scripts (`verify_physics.sh`, `reproduce_benchmark.sh`, `rdturbo_eval.sh --stall-timeout`) rather than ad-hoc
  loops: they check the tree and the switches before running, and `reproduce_benchmark.sh` restores the tree on exit.
