# RoboDojo-Turbo 0.1.0a1 (preview)

Evaluate policies on [RoboDojo](https://github.com/RoboDojo-Benchmark/RoboDojo) 1.4-2.4x faster on the same machine,
with the same physics and scoring code (Pi_05 policy, one RTX 5090 + Ryzen 9 9950X3D, four tasks). Unofficial: not
affiliated with or endorsed by the RoboDojo maintainers; results are not official leaderboard entries.

This is a work-in-progress preview. It patches a local RoboDojo checkout (pinned to RoboDojo 726e9aa / XPolicyLab
bb9a0b5) so that the same evaluation runs faster, with every switch off by default, a byte-exact `revert`, and check
modes and replay tools to verify that physics and scoring are unchanged.

## What was validated (one RTX 5090, Isaac Sim 5.1, pre-release builds of 2026-09-27/28)

- `stack_blocks`, official layouts 0-9: PhysX state bit-identical under open-loop replay with every switch off and with
  the speedup preset (5,208/5,208 states).
- 11 more tasks, official layouts 0-9, every check mode on, closed loop: 0 byte/bit mismatches in every dual-path check that
  ran; no swallowed batches in the legs that completed. 101 of 110 layouts were evaluated (RoboDojo dropped four as
  unstable; one task's run hung after its first batch, see Known limitations).
- `store_laptop_and_headphones`, 6 open-loop replays: PhysX state bit-identical with the USD write-back switch on and
  off; identical scores on all 10 layouts (1/10 successes in every replay, so this says little about borderline scores).

## Speed (same machine)

Official 25 layouts per task, RTX 5090 + Ryzen 9 9950X3D: `stack_blocks` 636 s unmodified upstream vs 299 s with the
speedup preset (2.13x; two alternating repetitions), `make_kong` 2.37x, `pick_from_conveyor_by_image` 2.10x,
`pour_liquid_into_cup_random` 1.36x (fluid, 5 environments per batch; one run per arm). Physics under open-loop replay is
bit-identical with every switch off and with the speedup preset. The chunk-start images the policy receives are within
render noise with the video-only observation switch on and off. Closed-loop scores pooled over the four tasks (125 paired
layouts): +0.7 points, 95% CI [-4.2, +5.5], 16 vs 15 successes; per task the samples are small (the same code repeated
on stack_blocks moved by 12 points). The speedup preset
keeps a JAX compilation cache (about 6 s per run); the upstream arm compiles on every run.

## Known limitations

- `RDTURBO_USD_LAST` leaves bodies that fall asleep during an action stale in USD: up to 1.2 mm and ~6 degrees on 5 of
  11 tasks checked (none on `stack_blocks`). What is rendered, and USD-reading scorers, can see that stale pose.
- `store_laptop_and_headphones*`: two closed-loop runs with that switch on hit a CUDA error in PhysX's GPU narrowphase
  and one of them hung; one run with it off did not; six replays did not reproduce it. Cause undetermined; the
  launcher's `--stall-timeout` stops such a hang.
- Pi_05 policy and joint actions only for several switches; one machine and one Isaac Sim version tested; Linux only.
