# Changelog

## 0.1.0a1 (work-in-progress preview, unreleased)

First preview. Use it from a git checkout: the launcher and verification scripts live in `scripts/`; the Python package
(`pip install .`, command `robodojo-turbo`, or `python -m robodojo_turbo` from the checkout) carries the patcher CLI,
runtime modules, presets and analysis tools.

Pinned upstream: RoboDojo 726e9aa, XPolicyLab bb9a0b5 (d6332bf leaves the patched files unchanged); validated on
Isaac Sim 5.1 / Isaac Lab 2.3.2 / omni.physx 107.3.26, one RTX 5090 + Ryzen 9 9950X3D.

### Added
- Reversible, hash-pinned patcher (`apply|revert|status|pins|check-env|list|env`): 19 patches in three profiles
  (`harness`, `speedup`, `all`), declared dependencies, upstream-API presence checks, byte-exact revert, rollback of
  interrupted applies, scratch-copy dry run; a patched tree whose state directory was deleted is reported (never passed
  as upstream) with exact restore commands.
- Harness: layout sharding, one policy server per worker, span tracing and bubble report, chunk-start observation upload
  for the Pi_05 loop, lossless fast path, optional x264 thread cap, accounting of batches RoboDojo's generic exception
  handler swallows (`RDTURBO_STRICT=1` exits non-zero).
- Ten speedup switches, each off unless set (docs/switches.md), with check modes where a dual path exists; values
  outside a switch's documented set mean upstream behaviour.
- Ops: skip the unused cuRobo planner for joint actions, offline mirror of the nine NVIDIA material files, overridable
  server memory fraction.
- Launcher `scripts/rdturbo_eval.sh` with guards (EULA never accepted for the user, patched-tree and switch consistency,
  strict switch values, port checks), unique run ids, a stall timeout, cleanup on every exit path, merged results that
  separate RoboDojo's unstable layouts, stacked presets (`--preset speedup,verify`).
- Verification: open-loop action record/replay, float64 state traces (robot, rigid and articulated objects), USD-side
  particle/cloth traces, chunk-start observation dumps, `tools.state_compare`, `tools.particle_compare`,
  `tools.paired_compare` (paired bootstrap CI, exact McNemar, MDE80), `scripts/verify_physics.sh` (the PhysX state
  decides; USD-side link transforms are reported separately; strict replay), `scripts/reproduce_benchmark.sh`
  (`--legs` picks which legs run, e.g. `upstream,speedup`; `--same-jax-cache` gives every arm the same JAX compilation
  cache); `tools.paired_compare` pools several run pairs with a bootstrap stratified by pair.
- README figures generated by `scripts/make_figures.py` (standard library only) from `docs/data/benchmark.json`, light
  and dark variants.
- GPU-free tests (patch matrix against pinned upstream, exact upstream Pi_05 call sequence, injected code with stubs).

### Validated on a GPU with pre-release builds (2026-09-27/28, docs/validation.md)
- Multi-task check-mode run, closed loop, 11 tasks (official layouts 0-9) + 1 control leg: 0 byte/bit mismatches in
  every dual-path check that ran (video frames, control resolution incl. a franka support arm, parent transforms,
  control-dict copies, joint-target tensors); no swallowed batches in the 11 legs that completed; offline assets
  verified on every task; fluid and cloth points never froze. 101 of 110 layouts evaluated: two tasks lost two layouts
  each to RoboDojo's stability check, and `store_laptop_and_headphones_random` hung after its first batch (below).
- `store_laptop_and_headphones` open-loop replay A/B (6 replays): deterministic; PhysX state bit-identical with
  `RDTURBO_USD_LAST` on and off; identical scores on all 10 layouts (1/10 successes, score 30.0 in every replay).
- `stack_blocks`, `scripts/verify_physics.sh` (official layouts 0-9): every switch off vs the speedup preset, 5,208/5,208
  PhysX states bit-identical under open-loop replay.
- `stack_blocks`, `scripts/reproduce_benchmark.sh` (official 25 layouts, 2 alternating repetitions, same machine):
  wall clock 636 s upstream, 546 s harness, 299 s speedup (2.13x vs upstream; 1.83x vs harness). Closed-loop scores at
  n = 25 are within the same-code repeat noise (12 points), with the speedup arm lowest in both repetitions.
- Three more tasks, official 25 layouts, one run per arm: `make_kong` 939 -> 396 s (2.37x), `pick_from_conveyor_by_image`
  943 -> 450 s (2.10x), `pour_liquid_into_cup_random` 1098 -> 805 s (1.36x, 5 envs per batch).
- The current identifiers were re-checked on 2026-09-28: patched trees identical to the 2026-09-27 build apart from
  identifier names; `stack_blocks` layouts 0-9 speedup closed loop 115 s, rc=0.

### Validated on a GPU with this code (0.1.0a1, commit eba171e, 2026-09-29)
- Four tasks, official 25 layouts, two runs per arm (official, Turbo, Turbo, official), same JAX compilation cache in
  both arms: `stack_blocks` 639.5 -> 297.5 s (2.15x), `make_kong` 913 -> 397.5 s (2.30x), `pick_from_conveyor_by_image`
  911 -> 443.5 s (2.05x), `pour_liquid_into_cup_random` 1008.5 -> 753 s (1.34x, 5 envs per batch); two runs of the same
  arm within 1.9%.
- Closed-loop scores over all 13 official-vs-Turbo run pairs (8 with this code, 5 with the 2026-09-27/28 pre-release
  builds and a Turbo-only warm JAX cache; 325 paired layouts): official 39, Turbo 40 successes, +0.2 points, 95% CI
  [-3.0, +3.4], exact McNemar p = 1.0, MDE80 4.6 points (6.0 without the conveyor task, which had no successes); the 8
  new pairs alone: 24 vs 24, -0.1 [-4.2, +4.0].

### Known limitations and issues
- Timing: four tasks, one machine, the Pi_05 policy; cloth and articulated-object tasks, other hosts and GPUs are
  unmeasured. In the 2026-09-27/28 runs only the speedup arm had a warm JAX compilation cache (about 6 s per run); the
  2026-09-29 runs give both arms the same cache.
- Scores: pooled over the four timed tasks (325 paired layouts, three or four runs per arm) the difference is +0.2
  points, 95% CI [-3.0, +3.4]; per task, changes below about 8-14 points would go undetected. Physics is bit-identical under open-loop replay on `stack_blocks` and
  the chunk-start images the policy receives are within render noise with `VIDEO_ONLY_OBS` on and off.
- `RDTURBO_USD_LAST` leaves bodies that fall asleep during an action stale in USD: up to 1.2 mm and ~6 deg (eggs,
  `fill_egg_holder`), 0.3-0.9 mm on the other affected tasks, 5 of 11 tasks, none on `stack_blocks`. The rendered pose
  of such bodies can lag PhysX by that much (effect on frames not measured), and USD-reading scorers see the stale pose
  (no score changed in the 10-layout laptop replay, which has little power).
- `store_laptop_and_headphones*`: 2 of 2 closed-loop runs with `USD_LAST` on (all check modes on) hit a CUDA error in
  PhysX's GPU narrowphase, one of them hung; 0 of 1 with it off (different builds). Not reproduced in 6 open-loop
  replays, which do not run policy inference. Neither attributed to the switch nor ruled out.
- Pi_05 only for chunk-start upload, `VIDEO_ONLY_OBS` and `USD_LAST`; joint actions only for `NO_PLANNER`.
- Validated on one machine (RTX 5090, Isaac Sim 5.1); other GPUs and Isaac Sim versions are untested. Linux only.
